# volume-review-runbook

## 役割

刊行前の分冊を、レンズ別のサブエージェントで通しレビューするときの回し方を決める。
**何を見るかは既存の `agents/*.md` にある。この文書は、それをどう回すかだけを書く。**

対象は分冊の正本、`books/volume01-core-patterns/output/` の7ファイルである。
`output/` の同名章は供給元であって分冊とは一致しないので、混ぜて読ませない。

## 章で割らず、レンズで割る

**1体に1章を割り当ててはならない。** 本書の欠陥の多くは、同じ言い回しが3章で
少しずつ違う、同じIDが章によって別名で呼ばれる、といった**章をまたいだ食い違い**である。
章で割ると、どの1体もそれを見られない。

**1体につきレンズを1つ、そのレンズで全7ファイルを読ませる。** 5つのレンズを回すなら、
5体がそれぞれ7ファイルを見る。

## 1体ずつ順に走らせる

**5体を同時に起動すると、セッションの回数制限に当たる。** 実測で、5体並列は
数万行の同時読み込みになり、2回とも制限に達して全体が止まった。
**1体が終わってから次を起動する。**

各エージェントには次を必ず渡す。

- **原稿を編集しない。** 書いてよいのは `reviews/agent-<レンズ名>.md` だけ
- **grepで当たりを付けてから読む。** 3,000行のファイルを頭から読ませない
- **見つけたそばからレポートへ書き足す。** 最後にまとめて書くと、途中で
  尽きたときに何も残らない
- **行番号は変わる前提で、原文の引用を必ず添える。** メインスレッドが
  並行して直しているので、レビュー中に行番号がずれる

## 報告の形

1件につき次の4つを書かせる。**「検算した結果」が無い指摘は採用しない。**

| 欄 | 中身 |
|---|---|
| 原文 | 本文からの逐語引用（行番号だけでは足りない） |
| 検算した結果 | 何と突き合わせて、実際はいくつだったか |
| 読者がどう困るか | その食い違いで、読者が何を確かめられなくなるか |
| 直し方 | 置き換える文の案 |

**判断が付かないものは「保留」へ回させる。** 著者の意図が要る箇所を
無理に指摘へ格上げすると、正しい記述まで書き換わる。

## 5つのレンズ

| レンズ | 見るもの | 検算の当て先 |
|---|---|---|
| 論理と数 | 「3か所すべてで」「差分は2点」「5つの問いで」のような数の主張 | 直後の表の行数、図のノード数、掲載コードの該当行数 |
| 言葉 | 一語ずつの正確さ。比喩、指示語、同じものの呼び分け | 同じ対象を指す他の箇所、IDの確定表 |
| ノイズ | 消しても読者が困らない段落、編集の舞台裏、当たり前の弁明 | その段落を消して意味が減るか |
| 表と図 | 本文の主張が、その表・図から実際に読み取れるか | 表の列と行、図のノードと色分け、現状図との差 |
| 初読 | 上から1回だけ読む読者が、そこで詰まらないか | 初出の識別子、前提の置き場所、前後の行き来 |

各レンズの詳細な観点は既存の Agent を使う。論理は `logic-check-agent.md`、
言葉は `clarity-agent.md`、初読は `readability-agent.md` と `review-agent.md`、
表と図は `structure-agent.md` と `consistency-agent.md` が対応する。

## 受け取る側の作法

**エージェントの指摘は入口であって結論ではない。** 全件を自分で実物に当ててから直す。
外れることがあるし、当たっていても原因の見立てが違うことがある。

実例。「変更後の図で、もとからあって変わったノードが4つあるのに『変わったノードは
ありません』と書いてある」という指摘は、事実としては当たっていた。しかし4つのうち
判定ノードは、**コード上は何も変わっていないのに図だけが書き換わっていた**もので、
正しい直しは「変わったと本文へ書く」ではなく「図を元へ戻す」だった。
指摘のとおりに直していたら、変わっていない判定を変わったことにしていた。

数の主張は、必ず**数え直してから**直す。エージェントが挙げた行番号を信じない。

## 直した後に回す検査

```
python3 script/check_volume.py --config books/volume01-core-patterns/publishing/book.json
python3 script/run_completion_gate.py
```

`check_volume.py` は表のセル幅（6インチ端末）も見る。指摘を反映して本文や表を
長くすると、ここで落ちる。落ちたセルは、CLAUDE.md の規約どおり
**そのセルだけ名前を外す**か、内容を表の外の一文へ出す。

`run_completion_gate.py` の `FAIL: Mermaid rendering` は、並列レンダリングの
タイムアウトで出ることがある。`script/check_mermaid.py` を単体で通して
全図が描けるなら、原稿側の問題ではない。
